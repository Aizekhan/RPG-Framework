# Changelog

## [Unreleased]

## [0.6.0] - 2026-10-28

Fixes from the MythRunner audit (a runner + action RPG on the kit, co-op 1-4). **Co-op protocol version 10**: 0.5.1 builds are refused. Install with `#v0.6.0`. A game that hand-rolls loot, prices, cooldowns or timers in its rules now fails GA14: move it to the modules (recipe 16) or record the gap.

### Changed
- **Ability range is checked in kit games.** `ActionRpgHost` never set `ActionRpgModule.Distance`, so `Range` on an ability was ignored. Now `ActionRpgHost.AbilityDistance(caster, target)` measures it (scene distance by default; a runner or grid game overrides it with its own measure).
- **`TradingManager` keys proposals per player** (two players proposing the same offer no longer collide), re-checks an offer's uses when accepting, and the "Wrong entity for this trade" failure is gone (another player's proposal is "Trade not proposed").
- `ActorWorld`'s constructor takes an optional `ICurrencyWallet` last; `IActorWorld` has `CurrencyOf` and `TakeOffer`; `PlayerProgress` and `PartyStatus` carry `Currencies`; `CoopIntentMessage` has `TakeOffer` and `OfferId`.

### Fixed
- **The game CI workflow no longer passes without running a test.** Without the `UNITY_LICENSE`/`UNITY_EMAIL`/`UNITY_PASSWORD` secrets the run fails with an error (it used to skip every step and show green; MythRunner's CI "passed" in 8 seconds for a month). An EditMode run that reports 0 tests fails too. Reinstalling the AI guidance replaces the old framework workflow; a workflow the game wrote or changed is kept. Checkout fetches LFS files.
- **Co-op keeps running when the window loses focus.** `ActionRpgHost` sets `Application.runInBackground` when it hosts or joins: an Alt-Tab on the host froze every friend.

### Added
- **GA14 "The game's rules use the framework's gameplay modules"**: rules code that hand-rolls a weighted pick or a random amount of currency (Loot), takes currency from a balance (wallet, Trading), counts down a cooldown (Abilities), an effect timer (StatusEffects) or any countdown (timers) fails. GA11 only caught a framework type rebuilt under its own name. Only a `// framework-gap: <id>` marker (on the line, above it, or above its type) lets one through; `architecture: allow GA14` does not. Recipe 16 maps each game need to its module (a chest → loot table, a shop → Trading, a perk → Abilities, poison → StatusEffects).
- **A currency wallet**: `ICurrencyWallet` / `CurrencyWallet` (`Balance`, `CanAfford`, `Add`, `TrySpend`, `SetBalance`, `BalancesOf`, `Forget`), `CurrencyChangedEvent`, `Currencies.Gold`.
- **Trading runs a shop**: `TradingManager` pays from an `ICurrencyWallet` and moves items through an `ITradeInventory` (requested items and money are checked first, a failure undoes everything), `ITradingManager.Trade(player, offerId)` proposes and accepts in one call, and `TradingModule` (Bootstrap.Gameplay) registers it. Before, its gold lived in a private dictionary with 1000 for everyone and no items moved.
- **Gold and shops in the action RPG kit**: `ActionRpgSettings.Currencies` (gold): a loot table entry with that id pays its quantity range into `ActorWorld.Wallet`, quest `Currency` rewards pay too; `CurrencyOf`, `GiveCurrency`, `SpendCurrency`, `Trade` / `TakeOffer` (the kit adds `TradingModule` with `ActorTradeInventory` over the backpacks). Money follows the progress mode (own wallet or the party's), is saved with the progress, reaches friends' HUDs, and a friend's purchase runs on the host. The character sheet shows gold.
- **Kit games off free 3D** (runners, lanes, grids): `ActionRpgHost.AbilityDistance` (above) and `ActorAbilities.ResolveTarget` (who an ability used without a target hits; runs on the host for friends too). Recipe 17: another genre on the action RPG kit (the game's space in one class, its actions as ability effects, timed states as status effects, one feature per module).
- **Co-op rejoin keeps the game's records**: `CoopHost.PlayerRejoined(previousId, newId)` comes right before `PlayerJoined` when a lost player is back within the rejoin window, so the game can hand their runner and loot back to the new id.
- **The host checks brought profiles**: `CoopHost.ProfileValidator` (`IGuestProfileValidator` → `GuestProfileCheck.Accept` / `Fresh` / `Refuse`). A player's own profile is taken once per session (by name): coming back after leaving, they continue with what they left with, not with what their machine sends.
- **A channel for state that changes all the time**: `CoopHost.SendLatestToAll(message, final)` sends unreliably with a sequence (the last one of a series reliably), `CoopClient.OnLatest<T>` drops a packet older than one already handled. For a game snapshot sent 10 times a second instead of a reliable full one.
- **Every address friends can reach** (MythRunner FG-11): `LanSessionProvider.LocalAddresses()` lists the home network first, then Tailscale / Radmin / ZeroTier ranges; `HostedSession.OtherJoinCodes` and `ActionRpgHost.OtherJoinCodes`, shown in the co-op panel. Before, only the first address was offered.
- New Game sets the Player Settings a game needs: Run In Background, Linear colour space, and a company name instead of `DefaultCompany` (the game's name, or `-company "<Studio>"`; a company already chosen is kept). `GameScaffold.ApplyProjectSettings`.
- Install AI Guidance writes a `.gitattributes` (when the project has none) that keeps models, textures, audio, video, fonts and archives in Git LFS. `START-NEW-GAME.md` step 3 runs `git lfs install`.
- AI guidance: "After the framework is updated" in the `CLAUDE.md` block, and the `FRAMEWORK-GAPS.md` template: after an update every open gap is checked against the changelog and its stand-in replaced (MythRunner kept FG-04/05 stand-ins after 0.5.0 covered them).

## [0.5.1] - 2026-10-27

Co-op across scene changes (hub and runs), and 0.5.0's rules reachable from the Game Setup. Co-op protocol version 9: 0.5.0 builds are refused. Install with `#v0.5.1`.

- **The 0.5.0 rules reach games built on `ActionRpgHost`.** Game Setup > **Co-op progress**: Progress Mode (Shared / Per Player) and Loot To Backpack (`GameSetup.SetProgress`). New `ActionRpgHost.ConfigureSettings(settings, content)` adjusts what the asset builds before the game starts (damage calculator, status effects, abilities); it runs on every machine, so host and friends keep the same fingerprint. Recipe 11 lists game messages, per-player progress, scene changes, owner defence, speed boosts and respawn points

- **The game and its co-op session outlive a scene change** (a hub and runs in scenes of their own). `ActionRpgHost.ChangeScene(sceneName)` loads the scene through `ISceneDispatcher` without ending the game: the party, progress, characters and the co-op link stay; an `ActionRpgHost` in the new scene steps aside (so each scene still plays on its own in the Editor); the camera follows the player there; `OnSceneChanged(sceneName)` places the players with the new `TeleportPlayer(playerId, pose)`. Joined machines load the host's scene, and so does anyone who joins later (`CoopHost.ChangeScene`/`Scene`, `CoopClient.Scene`/`SceneChanged`, `CoopSceneMessage`). Co-op protocol version 9: older builds are refused
- Fix: pools lost their objects on a scene change. `GameObjectPool`'s own container is kept across scene loads (it was a scene object, so loading a scene destroyed the pooled instances the pool still handed out); pools owned by a scene are still released with it

## [0.5.0] - 2026-10-27

Gaps MythRunner found in the action RPG kit and its co-op (FG-01..FG-08), plus what its design document needs from any co-op action RPG. Co-op protocol version 8: older builds are refused. Install with `#v0.5.0`.

- **Attacks carry their context (FG-03).** `AttackContext` (attacker, target, a tag mask, a source id, effect damage or not) goes through `ActorWorld.Attack(a, t, context)` and `DealDamage(attacker, target, amount, context)` to `IContextualDamageCalculator`; `ActionRpgSettings.DamageCalculator` sets a game's own (otherwise the container's). `ActorDamagedEvent.Context`; effect damage ignores defence in the default calculator. The tags travel to co-op guests
- **Status effects and abilities in the action RPG kit (FG-04, FG-05)**, optional: `ActionRpgSettings.UseStatusEffects` / `UseAbilities` (on when the content has any). `ActorEffects` (apply, remove, ticks; stats, health, movement and controls through `ActorEffectTarget`; cleared on death and despawn), `ActorAbilities` (`SetEffect(abilityId, effect)`, stun and silence block casting, `ReduceCooldowns`). `IActorWorld.EffectsOn`, `UseAbility`, `CooldownLeft`; `Actor.MoveMultiplier`, `IsStunned`, controls. In co-op only effect start and end and cooldown starts travel, reliably; late joiners get what is on
- **Speed boosts and settling (FG-06).** `CoopHost.SetAllowedSpeedMultiplier(playerId, k, duration)` and haste effects widen the movement check; after a teleport or correction the host lets the guest settle (`SettleTime`)
- **Respawn points (FG-08).** `IRespawnPointProvider` (`CoopHost.RespawnPoints`) places rejoining and revived players; without one nothing changes. `ActorWorld.RevivePlayer(playerId, reviverId, healthFraction)`, `Heal`, `ActorHealedEvent`
- **Owner-decided defence (FG-07).** `CoopHost.DefenseAuthority = Owner`: an attack on a guest is announced (`IncomingAttackEvent` on their machine), they answer `CoopClient.Defend(attackId, Dodged|Blocked|Hit, multiplier)` within `DefenseWindow`; no answer lands in full, answers to unknown or settled attacks are counted in `RejectedDefenseResults`. `AnnounceAttack(a, t, windUp, context)` for telegraphed hits. `DefenseResolvedEvent`
- **A game's own messages over the co-op link.** `CoopGameMessages.Add<T>(id, authority)` with ids from `CoopProtocol.FirstGameMessageId` (1200); `CoopHost.On<T>/Send/SendToAll`, `CoopClient.On<T>/Send`. `ActionRpgHost.ConfigureCoopMessages`, `OnCoopHostOpened`, `OnCoopClientCreated`
- **Progress of each player's own (FG-01, FG-02).** `ActionRpgSettings.ProgressMode = PerPlayer`: level, experience, backpack, quests and kills per player (`LevelOf`, `InventoryOf`, `KillsOf`, `ActiveQuestsOf`, `GrantExperience`, `CaptureProgress(playerId)`); a guest brings their saved progress (`CoopClient.Profile`), sees their own in the HUD and takes home `RemoteWorld.CaptureProgress()` (kept after the link is lost); a rejoining guest gets theirs back. `GiveItem(playerId, item, qty)`; `LootToBackpack = false` only announces drops for whoever picks them up. `ActionRpgSaves.ForProgressOnly` saves a guest's progress without touching the rest of the save (`SaveGameCoordinator.KeepUnknownSections`). `Shared` stays the default

## [0.4.0] - 2026-10-27

Gaps the turn-based rules found, closed before the API is frozen in 1.0: stat growth per hero, abilities that hit a whole side, forgetting an entity, Abilities and StatusEffects feature modules. Some interfaces gained members (listed below); implementers add them. Install with `#v0.4.0`.

- **Stat growth per hero or class.** `IStatGrowthFormula` takes growth profiles: `RegisterStatGrowth(profileId, data)`, `AssignProfile(entityId, profileId)`, `GetProfile`, and entity overloads of `CalculateStatAtLevel`, `GetStatChangesForLevelUp` and `HasStatGrowth`. A profile overrides the stats it has; the rest use the shared growth, which works as before. `StatGrowthPublisher` publishes each entity's own growth. Implementers of `IStatGrowthFormula` add the new members. TurnBased registers every hero's `CombatantData` as a profile (`TurnBasedWorld.GrowthProfilePrefix`), so its level-ups now publish `StatIncreasedEvent`; `CombatantData.Growth(stat)` gives the Progression growth and `StatAt` uses it
- **Abilities that hit a whole side.** `TargetType.AllEnemies` and `TargetType.AllAllies` need no picked target and ignore range; the game resolves the side in its effect callback. TurnBased maps them to `TargetScope.AllEnemies` / `AllAllies`
- `IAbilityExecutor.UnregisterEntity(id)` forgets an entity: ability instances and charges, a cast or channel in progress (dropped without events), toggles and cooldowns. TurnBased calls it for the enemies of a finished battle, so a new enemy with a reused id starts fresh. Implementers add it
- **New feature modules** `AbilitiesModule` (`IAbilityRegistry`, `ICooldownTracker`, `ITargetValidator`, `IAbilityExecutor`; `AbilitiesOptions` for range, relationships and resource maximums) and `StatusEffectsModule` (`IStatusEffectManager`; `StatusEffectsOptions.Target` or a registered `IStatusEffectTarget`) in `RPGFramework.Bootstrap.Gameplay`
- `IStatusEffectManager.RegisterEffect` (both overloads) is on the interface, so a manager resolved from the container can be filled. Implementers add them

## [0.3.0] - 2026-10-27

Co-op stage 3 (reliability) and PvP, saves that outlive builds, designer assets for every content module, modules that do what their assets say, the rules of a turn-based party RPG, and core services wired in and enforced for games (GA13). Install with `#v0.3.0`.

- **A second genre: the rules of a turn-based party RPG** (`TurnBased`, JRPG style), built on the framework's modules rather than beside them: Abilities (mana costs, cooldowns in rounds), StatusEffects (poison and regen tick on the affected combatant's turn, stun skips it, stat buffs and debuffs), Progression (levels and per-hero growth), Items, Inventory and Loot (consumables, rewards). `Battle`: turn order by Speed, `Perform(BattleAction)` for Attack, Ability, Defend, Item and Flee, refusals in plain words, `IBattleAi` (default `SimpleBattleAi`), `IBattleFormula` (seeded). `TurnBasedWorld` / `ITurnBasedWorld`: the party, inventory, gold, a run of encounters, rewards, rest, restart; `TurnBasedSaves`; events on the bus; `TurnBasedComposition.Configure`. No battle screen yet: the game builds its views (recipe 15). 47 tests, including a whole run played to the end and a save mid-run
- `StatusEffectManager.RemoveAllEffects` on an entity that no longer exists does nothing (it threw)
- The package README lists the genres and what each one gives; recipe 15 (turn-based) and the AI guidance point a new game at the right kit
- **Games use the framework's core services instead of rebuilding them.** New `UnityServicesModule` (`RPGFramework.Bootstrap.UnityServices`) registers shared `IPoolManager`, `IAssetManager` (Resources; `UnityServicesOptions.AddAssetProvider` adds Addressables or others), `IPrefabSpawner` (loads through that asset manager, pools in that pool manager) and `ISceneDispatcher` (Unity scenes, events on the bus); pools owned by a scene go when it unloads, and shutdown releases pools and unloads assets. A service registered before it is kept. `ActionRpgHost` adds it and takes its spawner from the container (it built a private one before); `ConfigureUnityServices(options)` adds asset sources; the F3 panel now shows pools (`UnityServicesModuleTests`). New architecture rule **GA13** "The game uses the framework's core services": game code using `Resources.Load`, `SceneManager.LoadScene`, `Debug.Log`, `Invoke`/`InvokeRepeating`, `new WaitForSeconds`, `Instantiate`, `Destroy` (not of a `GetComponent` result) or a hand-made pool fails, naming the service to use; a line with a reason opts out with `// framework-ok: <reason>`. Every game's `<Game>ArchitectureTests` gets it; the action RPG views pass it (five lines opt out with reasons, checked by `GA13_TheFrameworksOwnActionRpgViews_UseTheCoreServices`). New recipe 14 "core services": need, service, not that, for the core runtime (logging, events, timers, systems, phases, ECS, archetypes, queries, async), Unity services, AI helpers (state machines, behaviour trees, pathfinding), UI navigation and diagnostics; `CLAUDE.md`'s framework block and START-NEW-GAME.md point to it. New Game projects reference timers, pooling, scenes and the services module
- **Modules now do what their assets say.** Building the designer assets showed several modules ignoring part of their data; each fix is proven by tests that fail on the old code:
  - **Dialogue:** conditions and Branch nodes work. Moving on takes the first next node whose condition passes; Branch nodes are passed through (with their own condition they act as if/else); choices whose condition fails are neither offered nor selectable; a start node whose condition fails does not start. `DialogueManager(..., events, contextProvider)` gets the `IDialogueContext` per entity (no context: conditions do not pass). `DialogueStartedEvent`, `LineSpokenEvent`, `ChoiceSelectedEvent`, `DialogueEndedEvent` are now published on the bus (they were built and thrown away). Fix: starting crashed when the stored component had no dialogues yet (`DialogueFlowTests`; one old test expected a gated choice to be offered without a context)
  - **Abilities:** cooldowns live in `CooldownTracker`; abilities with a cast time pay, land, start their cooldown and send the executed event when the cast completes (`CompleteCast`, `Update(time)`), and a cancelled or interrupted cast costs nothing (`InterruptCast` honours `IsInterruptible`; the cancel event carries the time). Passive abilities cannot be used; toggles switch on and off (`AbilityToggledEvent`); channels keep the caster busy for `ChannelDuration`; one cast at a time per caster. Percentage costs are a share of the resource maximum (optional `resourceMaximum`; refused when unknown, not charged wrongly); targets are checked when used and again on completion (optional `distanceCheck`, `relationshipCheck`) (`AbilityRulesTests`)
  - **StatusEffects:** modifiers are applied. New optional `IStatusEffectTarget` (`StatusEffectManager(entities, events, target)`): stat modifiers go on when the effect is applied, follow its stacks and come off on removal or expiry; resource modifiers apply each tick by their operation; `GetMovementMultiplier`, `IsControlled`, `GetActiveControls`. New `Integration/StatusEffectsStats`: `StatContainerEffectTarget<TStatType>` puts effects on a `StatContainer`. `RegisterEffect` returns false for an id already taken instead of ignoring it silently (`StatusEffectApplyTests`, `StatContainerEffectTargetTests`)
  - **Crafting:** recipe requirements are checked before a craft starts (they always passed). Stations by the manager (id or type, minimum level), tools in the `ICraftingInventory` (not used up), skills and quests through a new optional `ICraftingRequirementChecker`; without one such recipes are refused rather than allowed unchecked (`CraftingRequirementTests`)
  - **Skills:** `SkillTree.AddSkill` refuses a second skill with the same id (it dropped it silently); a prerequisite that names a skill without a level needs that skill known (it was always met) (`SkillTreeRulesTests`)
  - **Factions:** `IFactionRelationship.InvolvesFunction` is renamed `Involves` (implementers rename it; the old name stays on `FactionRelationship`, obsolete)
- **Designer assets for six more modules**, each with an inspector that lists problems in plain words, a conversion to the module's runtime data, and tests that run the converted data through the real module: **Dialogue** (conversation outline; unreachable nodes, dangling choices, dead ends, endless loops), **Faction Database** (relationship grid; builds the `FactionRegistry` PvP `FactionHostility` uses), **Skill** and **Skill Tree** (tiers; prerequisite loops), **Ability**, **Crafting Recipe** (ingredients and results are `ItemAsset`s; one-line summary), **Status Effect** (one-line summary). Tools > RPG Framework > Create makes them. The 9 custom inspectors in `Editor/CustomEditors` were removed: none ever showed (they targeted types that are not assets, or had no `[CustomEditor]`); Item, Loot and Quest keep their working editors in `Tools` (approved by the owner)
- **Fix: crafting never finished.** `CraftingManager.UpdateCrafting` was empty, so every craft stayed in progress forever (proven by failing tests). Crafts now advance, complete with the results their success chances allow, or fail when nothing came out or the recipe is gone. New optional `ICraftingInventory`: with it ingredients are checked and taken at the start, given back on cancel, and results handed out (`CraftingLifecycleTests`)
- **PvP as a mode.** Game Setup > PvP turns co-op into a match: **Duel** (rounds, first to Rounds To Win), **Team Deathmatch** or **Free For All** (respawn, first to Score To Win), with an optional time limit and automatic restart. Players get sides (fewest-players team, or their own in free-for-all), meet at their side's spawn points on every machine, and see the score and the match state in the HUD; tags take the side's colour. `PvpMatch` (`module.Pvp`), `IActorWorld.PvpStatus`, and events `PlayerDefeatedEvent`, `ActorTeamChangedEvent`, `PvpRoundStartedEvent`, `PvpScoreChangedEvent`, `PvpRespawnedEvent`, `PvpRoundEndedEvent`, `PvpMatchEndedEvent` (`PvpTests`, `CoopPlayTests` duel over real UDP)
- **Who may hit whom is a rule.** `IHostilityRules` (`ActionRpgSettings.Hostility`): co-op (players never hurt each other, also fixed: `ActorWorld.Attack` let a player hit a player), teams, or `FactionHostility` (factions at war fight). `ActorWorld.Attack` refuses friendly targets; `IActorWorld.AreHostile`; the player and enemies pick targets by it
- **The co-op host checks movement.** A joined player may not move faster than their character's `MoveSpeed` (now in `CharacterData`) allows; the host keeps them where they could have got to and corrects their own machine (`CoopCorrectionMessage`). `CoopHost.Teleport` moves a player on purpose on every machine. `IActorMotion.Teleport` is new (implementers add it). Co-op protocol version 4: teams and the match travel with the world; older builds are refused
- **Fix: Skills works on its own.** `SkillManager` stored nothing, so learning a skill always failed (proven by failing tests). Skills are now kept on the entity as a `SkillProgressData` component (now an `IComponent`), added with the first skill; a game can still store them elsewhere by overriding the two storage methods (`SkillManagerTests`)
- **Fix: loot without duplicates could hand out less than the table promised.** Items already dropped still counted in the total weight, so a roll could land on nothing (a 3-item table asking for 3 drops gave 2). Each roll now weighs only the items still allowed; tables with duplicates roll exactly as before (`LootGeneratorTests`)
- `IEntityManager.GetEntitiesWith<T1, T2>(List<int>)` and `<T1, T2, T3>(List<int>)`: allocation-free queries for several components (the array versions allocate on every call)
- **Benchmarks** (printed to the test output, generous budgets that catch regressions): ECS 1000 moving of 10000 entities 0.24 ms a frame with no garbage; EventBus 1000 events x 3 subscribers 0.13 ms with no garbage; `ActorWorld` with 1000 enemies, systems and 200 attacks 0.07 ms (rules only, without Unity views)
- **Events that were declared but never sent now arrive.** An audit found 50 of 97 event types that nothing ever created (a game could subscribe and wait forever). They now implement `IEvent` and are published where the thing happens, each proven by a test; managers take an optional `IEventPublisher` as their last constructor parameter (existing calls compile unchanged):
  - **Loot**: `ActorWorld` publishes `LootGeneratedEvent` then a `LootDroppedEvent` per item handed out when the party kills an enemy
  - **Networking**: `NetworkManager(..., events)` publishes `ConnectionEstablishedEvent`, `ConnectionLostEvent` (`WasTimeout` after a silent peer) and `MessageReceivedEvent`; `ReplicationSystem(config, events)` publishes `EntitySpawnedEvent` (from `SpawnEntity`, which did nothing), `EntityDespawnedEvent` and `StateReplicatedEvent`
  - **Achievements** (progress, criterion completed, unlocked), **Skills** (learned, level up), **StatusEffects** (applied, tick, expired, removed), **Companions** (summoned, dismissed, death, level up, fed, loyalty changed), **Housing** (purchased, furniture placed/removed, upgraded, guest invited), **Trading** (proposed, declined, accepted, completed), **DynamicEvents** (spawned, started, participant joined, objective progress, succeeded/failed, completed), **Items** (`ItemCreatedEvent` from `ItemInstance`)
  - **Environment**: `EnvironmentEffect.OnEffectApplied` raises `EnvironmentEffectAppliedEvent` when the effects in force change; all four environment events implement `IEvent`
  - Values a publisher does not know are documented on the event (a timestamp of 0 where the manager keeps no clock, `Guid.Empty` where it is not told who acted)
- **Removed** `ItemUsedEvent` and `ItemDestroyedEvent`: the framework has no use or destroy operation for items, so nothing could ever send them
- **Removed** three editor windows that were compiled out (`#if FALSE`) because they targeted asset types that do not exist: Quest Editor, Dialogue Graph Editor, Faction Relationship Map. Quests are edited as `QuestAsset`s; dialogue and faction editors are planned
- `SkillManager`: its storage helpers are `protected virtual` (they were private stubs, so learning a skill always failed); a game supplies storage by overriding them
- **Fix: `DeltaSerializer` rebuilt wrong states.** Proven before: a state that grew lost its new bytes, one that shrank kept stale ones, a delta built on a state the receiver never got (a lost packet) was applied silently, and a broken packet threw `EndOfStreamException`. Now a delta carries the new length and the length and checksum of the state it was built on: the receiver refuses a delta for a state it does not have (`InvalidOperationException`; the sender calls `ClearState` and sends a full state) and a broken packet (`InvalidDataException`), keeping its state. Changes are sent as byte runs, cheaper than the old 5 bytes per changed byte. The wire format changed (`DeltaSerializerTests`)
- **Fix: designer assets in `Tools`.** The loot table editor showed wrong drop rates when a table had an entry without an item (it counted weight the game never rolls: 37.5% shown for 75%). An empty prerequisite slot locked a quest forever; a quest asset made in code failed to convert (`NullReferenceException`). Checking a quest database with long branching chains froze the editor (17 s for 20 chapters; now each quest is walked once). Loot checks report entries whose max level is below their min level (they never drop). Consumable items get their effect from the asset (`ItemAsset.effectId`, `effectMagnitude`; the old placeholder stays the default) (`ToolsAssetTests`)
- **Fix:** the debug tools in `RPGFramework.Tools` (event logger, console, debugger, profiler, health monitor) read keys through the legacy input manager only and threw every frame in a game that uses only the Input System; they now read either, like `DiagnosticsOverlay`
- **Stats recalculate 18 times faster and allocate nothing.** `StatContainer` kept LINQ queries, sorting and boxing in every recalculation: a thousand characters with six modifiers each took 7.3 ms a frame and made garbage every time. Modifiers are now kept in priority order as they are added and summed in one pass without conversions that box: 0.4 ms a frame, no garbage (`StatContainerPerformanceTests`, with the benchmark numbers in the test output). Same results: an override still wins by priority, additives then multipliers in priority order
- **Fix:** a whole-number stat pushed past its type's limit (`int.MaxValue` plus a bonus) threw `OverflowException`; it now stops at the limit.
- **Saves outlive the build that made them.** Each save section carries its participant's version (`ISaveParticipant.Version`, `SaveParticipant<T>.Version` / `Upgrade`): older sections are upgraded by the participant, saves from before section versions load as version 1, and a save from a newer build is refused before anything changes (`SaveGameState` format 2). `SaveGameCoordinator.LastUpgradedSections`
- **A save is never lost to a bad load.** `SaveSystem` keeps the previous save beside the latest (`<slot>.previous.sav`, only when it was intact) and loads it when the latest fails its checksum or cannot be read (`LoadResult.FromPrevious`, `ISaveSystem.LoadPrevious<T>`); the coordinator falls back the same way when the latest is intact but its sections cannot be used. `SaveSystem.SetAside` moves an unreadable save out of the slot. `ActionRpgSaves`: unreadable saves are kept aside and the game starts fresh, a newer build's save is not saved over (`CanSave`, `Notice`), and the game log tells the player
- **Fix: the JSON save serializer** (`JsonSaveSerializer`, also inside `BinarySaveSerializer`) is rewritten as a real parser. Proven broken before: text ending in a quote or a backslash came back wrong or swallowed the next field; a literal `\n` became a line break; a dictionary key with `:` made the save unloadable; `DateTime`, `Guid` or a cycle overflowed the stack while saving; truncated text loaded silently. Now: full escaping, enums by name, `DateTime`/`DateTimeOffset`/`TimeSpan`/`Guid`/`decimal`/nullable/all integer types, sets, get-only collections, a depth limit with a clear error, strict text and tolerant shape (unknown members skipped, missing keep defaults). Older saves still load (enums as `{"value__":n}`, number keys without quotes)
- `ActionRpgSaves.Register(participant)` and `ActionRpgHost.ConfigureSaves(saves)`: a game adds its own state to the saved progress. Recipe 12: saving and changing what you save
- **Co-op survives bad links.** A lost link (a crash, a pulled cable, a laptop asleep) is noticed in 10 seconds instead of waiting for the transport, on both sides; the F2 panel says when a link is struggling (2 seconds of silence). The host keeps a lost player's seat, name and health for 2 minutes; their game reconnects by itself (up to 3 tries) with a token from the host and they are back as themselves ("Reconnected: back in your seat"), even when they come back before the host noticed. Leaving on purpose keeps no seat; closing the host is not mistaken for a lost link. Co-op protocol version 3: older builds are refused
- `Networking`: `NetworkConfig.ConnectionTimeout` now works (it was a TODO): `NetworkManager` drops a peer it has not heard from, with `PeerDropped(id, PeerDropReason.TimedOut)` before `PeerDisconnected`; `SecondsSinceHeard(id)`. `NetworkConfig.MaxBadMessages`: a peer sending more unreadable or not-allowed messages is dropped (`PeerDropReason.BadMessages`).
