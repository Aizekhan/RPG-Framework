# Changelog

## [Unreleased]

### Added
- Items: `RolledItems` keeps an item's rolled rarity and affixes in its id ("sword~2~sturdy=2;str_1=9"): `Compose`, `TryParse`, `BaseOf`, `Roll(baseId, pool, rarities, random, itemLevel, luck, kinds)`, `Create(id, baseItem, pool)` builds the same named item on every machine.
- Action RPG kit: gear that drops as loot rolls affixes when `ActionRpgContent.Affixes` is set (`Rarities`, `LuckOf(playerId)`): the gear's kind is the affix kind, the player's level the item level. Rolled items are built from the content (`ActionRpgContent.FindItem` / `FindGear`, `ActorWorld.ItemOf`); worn, they add a bonus per affix; backpacks, saves and co-op keep them by id (the co-op content fingerprint includes the affixes).
- TurnBased: `BattleMenu.For(battle, inventory)` (engine-free) lists the current party member's commands (Attack, each ability with its cooldown, Defend, each battle item with its count, Flee) as `BattleCommand`s with their targets, nothing to aim, or why they are closed, by the battle's own rules; `With(target)` aims one.
- TurnBased Unity layer (`RPGFramework.TurnBased.Unity`): `TurnBasedHost` (a `GameHostBehaviour`: the game fills `ConfigureGame(settings, content)`; enemies act one by one with `Enemy Turn Seconds` between them, the run is saved after every battle under the player's data folder and continued on start, `StartBattle`, `Act`, `NewRun`) and `BattleScreen` (built from code on the framework's panels: enemies, party, log, the turn's menu, a command then its target; between battles the next encounter or a new run; `Bind(world)` without a host).
- Combat: damage elements. `DamageResistances` (per entity, from several sources that add up: the character, each piece of gear, a buff; held between `MaxWeakness` -1 and `MaxResistance` 0.75; immunities; `Apply(entity, element(s), damage)` splits mixed damage) and `ElementResistance` for content.
- Action RPG kit: elemental hits. `ActionRpgSettings.ElementTags` maps attack tag bits to elements; `CharacterData.Resistances` (and the Character asset's "When hit" list) and gear bonuses "resist:<element>" set what a character resists; `ActorWorld.Resistances` for a game's own sources.
- Items: item sets (`ItemSet` with `WithBonus(pieces, stat, value)`, `ItemSets.BonusesFor(wornIds)`; distinct pieces count, rolled items count as their base). Action RPG kit: `ActionRpgContent.ItemSets`; the set a player wears earns the bonuses of as many pieces (stats or "resist:<element>"), refreshed on every change; `ActorGear.SetBonusesOf`, also in `BonusesOf`.
- Action RPG kit: elite enemies. `ActionRpgContent.EliteAffixes` (an `AffixPool` of `ActorStat` or "resist:<element>" bonuses, the character id as the kind) and `ActionRpgSettings.EliteChance` / `EliteRarity` / `EliteRewardMultiplier`: a spawned enemy may roll affixes at the player's level, takes the affixes' name ("Frenzied Goblin of Stone"), modifiers and resistances, and gives that many times the experience and loot rolls. `Actor.IsElite` / `EliteName` / `EliteAffixes`, `ActorWorld.MakeElite(entity, affixes)`, `EliteSpawnedEvent`. A friend's machine in co-op shows the base name.
- Action RPG kit: enemy levels. `ActionRpgSettings.EnemyLevels` (`One` or `PlayerLevel`) and `EnemyLevelOffset` (Game Setup > Enemies, with Elite Chance): enemies spawn at that level with their character's per-level growth; `CharacterData.ExperiencePerLevel` (Character asset) adds experience per level; `Actor.Level`.
- TurnBased: elements. `AbilityEffectData.Element` ("fire") and `CombatantData.Resistances` (resist, weakness, immunity); `TurnBasedWorld.Resistances` (a `DamageResistances`) for a game's own sources (gear, a ward). Plain attacks have no element.
- Action RPG kit: a status effect with a "resist:<element>" stat modifier (a fire-ward potion) grants that resistance while it lasts, added to the character's and gear's.
- Turn-based: critical hits - `DefaultBattleFormula.CriticalChance` and `CriticalMultiplier` (1.5), `CombatantData.CriticalChance` per fighter, `HitResult.Critical`, `TargetOutcome.Critical` and "(critical)" in the battle log. No roll is made while the chances are 0, so seeded battles replay as before.
- Turn-based: quests. `TurnBasedContent.Quests`, `TurnBasedSettings.StartingQuests` and `CompleteQuestsAutomatically`; the party's quests live on `TurnBasedWorld.QuestHolderId`. Beaten enemies advance Kill objectives (character id), items the party gets advance Collect ones (item id) and won encounters advance Explore ones (encounter id). Rewards: experience for every member standing, gold (Currency) and items. `AcceptQuest`, `CompleteQuest`, `ReportQuestProgress`, `ActiveQuests`, `CompletedQuests`, `HasQuests`. A new run takes the starting quests again (not the done ones). Saves keep active and completed quests (`PartyProgress.ActiveQuests`, `CompletedQuests`) without paying rewards again. `TurnBasedComposition` now composes `QuestsModule`; a game composing its own modules gets quests when it adds `QuestsModule`.
- Action RPG kit: critical strikes. New stats `ActorStat.CriticalChance` and `CriticalDamage` (`Actor.CriticalChance`, `CriticalDamage`; `CharacterData.CriticalChance` 0 and `CriticalDamage` 1.5; CharacterDefinition fields). Gear bonuses, affixes, set bonuses and status effects can raise them by name. A strike rolls with the attacker's chance and becomes `AttackContext.AsCritical(CriticalDamage)`. Hits the game already made critical are not rolled again, and no roll is made at chance 0, so seeded games replay as before.
- Action RPG kit: evasion and life steal. New stats `ActorStat.Evasion` and `LifeSteal`, set in `CharacterData` and the CharacterDefinition fields, and raised by gear, affixes and effects. A strike on a character with evasion can miss, which publishes `ActorEvadedEvent` and deals no damage. Effects and other damage still land. A strike from an attacker with life steal heals back that share of the damage dealt. No roll is made at 0. In co-op the host decides; guests see the outcome without the event.

## [0.18.0] - 2026-10-29

### Added
- **Settings** (`RPGFramework.Settings`, MythRunner FG-25): `ISettingsService` / `SettingsService` with typed options (`ToggleSetting`, `ChoiceSetting`, `SliderSetting`: steps, ends, wrap-around choices, `Fraction` for a slider control), groups, `Find` / `Toggle` / `Slider` / `Choice`, `ResetToDefaults(group)`, kept through `ISettingsStore` (a default is not kept, a bad kept value is ignored), `Changed` and `SettingChangedEvent`. Options made with a getter and a setter are bound to a service that keeps the value itself.
- `DisplaySettings` (group "Display"): screen size, window mode (full screen / borderless / windowed), quality, vertical sync, frame-rate cap, applied at once through `IDisplayOutput`; the defaults are the screen as it is, so a first start changes nothing. Phones and consoles get quality and the cap only.
- Unity: `SettingsModule` (PlayerPrefs `RPGFramework.Settings.<id>`, `UnityDisplayOutput`, and the volumes and the language when those modules are there: `SettingsBridges.AddVolumes`, `AddLanguage`), `SettingsRows.For(settings, localization)` builds a settings page on `ActionListPanel` (headings, `<` / `>`, Defaults; `settings.*` keys).
- `ActionRpgHost` 'Settings' (on by default) registers the module and applies the kept display options at start; `ActionRpgHost.Settings`.
- StatusEffects: `IStatusEffectManager.Reapply(entityId)` hands the target again what an entity's effects do (stat modifiers, movement, controls), for effects that came back with a save; safe to call twice.
- StatusEffects: `StatusEffectsOptions.UseStatContainers<TStatType>()` (and `TargetFactory`) lands effects on each entity's `StatContainer<TStatType, float>` through `StatContainerEffectTarget` without hand wiring.
- Abilities: channel ticks: `CastInfo.ChannelTickInterval` calls the ability's effect again on every tick of a channel up to its end (driven by `IAbilityExecutor.Update`; ticks due before a cancel or interrupt still land), `AbilityChannelTickEvent`, `AbilityChannelEndedEvent` (completed or stopped, with the reason and the tick count). Ability asset: 'Channel Tick Interval'.
- Abilities: charges that come back over time: `AbilityMetadata.ChargeRechargeTime` (one at a time), `IAbilityInstance.RefreshCharges` / `NextChargeIn`. Ability asset: 'Charge Recharge Time'.
- Dialogue: `IDialogueGameContext` (`CountItem`, `CheckCustom`) and a ready `DialogueContext` made of the game's answers (`QuestDone`, `ItemCount`, `Stat`, `Custom`).
- Action RPG kit: the event log goes through localization too: `kit.log.*` keys (`KitLog.Keys`, also in `KitTexts.Table()`), `IActorWorld.LogLines` (`LogLine`: the text to translate and its English, `In(localization)`), `ActorWorld.Announce(LocalizedText, english)` for a game's own lines. `Log` keeps the English lines. A joined machine shows the host's English lines.
- Pathfinding: `DistanceMap` (a Dijkstra map / flow field over any `INavigationGraph`): distances from the nearest of several goals, `NextStep` towards them and `StepAway` to flee for any number of chasers from one search, `PathFrom`, a `maxCost` to keep the search near.
- Crafting and Persistence events also go on the game's bus: `CraftingManager(..., events:)` publishes `CraftingStarted/Completed/Failed/CancelledEvent`, `SaveSystem.Events` publishes `SaveCreated/Loaded/Deleted/ErrorEvent` and `AutoSaveTriggeredEvent` (the event classes are `IEvent` now); the C# events stay.
- Items: random affixes (`AffixDefinition`, `AffixPool`, `RolledAffix`, `ItemAffixes`). `AffixPool.Roll(random, itemLevel, rarity, itemTags)` picks prefixes and suffixes by weight among those that fit the item level and kind, one per `Group`, with counts by rarity (`SetCount`; defaults Common 0 .. Mythic 6) and values on a `Step`; the same seed rolls the same item. `NameFor` builds "Prefix Base Suffix" (with an optional translate), `RerollValues` reforges, `ModifiersFor<TStat>(sourceId, affixes)` gives stat modifiers with ids "sourceId:affixId". `ItemAffixes.Get/Set` keep them on the instance's `CustomProperties["affixes"]` as one culture-invariant string. The action RPG kit's gear does not roll affixes yet.
- UI: `ActionListPanel.MaxHeight` (0 by default: grows as before): taller rows scroll in a window (mouse wheel, drag), a button selected with the keys or a pad is brought into view, `ScrollTo(row)`, `Scrolls`, `ScrollOffset`.
- Abilities: upkeep costs. `ResourceCost.PerSecond` (and `AbilityCostEntry.perSecond` in the ability editor): taken every second while a toggle is on or a channel lasts, not when used (using it needs one second's worth). A toggle the caster can no longer pay for switches off by itself (`AbilityToggledEvent.Reason`, e.g. "Insufficient MP"); a channel ends (`AbilityChannelEndedEvent` with the reason). Switching a toggle off pays the seconds up to the switch.
- Items: `RarityTable` (weights per `ItemRarity`, `RarityTable.Default()` 600/250/100/40/9/1): `Roll(random, luck)` picks a drop's rarity, luck (magic find) grows a rarity's weight by luck times its tier; `ChanceOf(rarity, luck)`.

### Fixed
- StatusEffects: `ProcessTicks` catches up the ticks missed in a long frame (up to `StatusEffectManager.MaxTicksPerCall`, reported as one total) and keeps the effect's own rhythm; it ran at most one tick per call.
- Dialogue: `ConditionType.Custom` asks the game (`IDialogueGameContext.CheckCustom`); it always failed. `ItemOwned` honours `RequiredValue` as the quantity (counted through `IDialogueGameContext`; a plain context can confirm one item only); it ignored it.

### Changed
- Interfaces with new members (a game's own implementation needs them): `IActorWorld.LogLines`, `IStatusEffectManager.Reapply`, `IAbilityInstance.RefreshCharges` / `NextChargeIn`.

### Added
- **Co-op lobby before play** (MythRunner, step 2 of the start flow): with `CoopHost.UseLobby` (`ActionRpgHost` 'Lobby', `UseLobby`) friends who join wait in a lobby instead of landing in the world. `CoopHost.Lobby` (`CoopLobbyEntry`: name, hero (loadout), ready; the host is Id 0), `SetLobbyChoice(ready, loadout)`, `AllReady`, `Kick(id, reason)`, `StartMatch(countdown)` / `CancelStart()`, `StartCountdown`, `LobbyChanged`, `MatchBegan`; the lobby counts towards `MaxPlayers`. ## [0.14.0] - 2026-10-28

### Added
- **Turn session** (`RPGFramework.Turns`, The Bloodline Hunt BH-01..03): a turn-based match over any transport (LAN, relay, `LoopbackNetwork`), its own protocol (`TurnProtocol`, version 1, message ids 1300-1311; `TurnProtocol.CreateNetwork(transport)`).
  - `TurnHost` (seat 0): `Open(port)` / `Open()`, a lobby (`Seats`, `SetReady`, `AllReady`, `LobbyChanged`), `Start(rules, options)`. Players with another `TurnHostOptions.Fingerprint` or protocol, joining a full table or a started match are refused with the reason.
  - The game's rules (`ITurnRules`: `CurrentSeat`, `CanAct`, `Apply`, `ViewFor(seat)`, `DefaultIntent`) run only on the host. Moves (`TurnIntent`: a kind, numbers, texts) are checked there, answered with a `TurnOutcome`, and every accepted one is in `Accepted` (seat, move) for the match record.
  - After every change each seat gets only its own view (`ViewFor`), so hidden cards stay hidden. `Notify(notice, TurnVisibility.All/Seat/Host)` tells what happened, for screens to show.
  - Reaction windows: `OpenPrompt(kind, options, seats, seconds, closed)`; answers are an option or `TurnPrompt.Pass`; time up or an away player is a pass.
  - `TurnHostOptions.TurnSeconds`: when a turn runs out the host makes `DefaultIntent`.
  - A player who drops in a match keeps the seat for `RejoinWindow` seconds and comes back with `TurnClient.RejoinToken`: the options, the view and the open questions are sent again.
  - `TurnClient`: `Join(address, port)` / `JoinSession(code)`, `Submit` (a request id, answered in `Replied`), `Answer`, `SetReady`, `Leave`, `State`, `EndReason`. Host and client share `ITurnSession`, so screens are written once.
- `ScriptedDice.Then(purpose, rolls)`: rolls scripted for a purpose ("fight") go only to rolls for it and come before the plain script; `RemainingFor(purpose)` (The Bloodline Hunt).

- **Removed** `ItemUsedEvent` and `ItemDestroyedEvent`: the framework has no use or destroy operation for items, so nothing could ever send them
- **Removed** three editor windows that were compiled out (`#if FALSE`) because they targeted asset types that do not exist: Quest Editor, Dialogue Graph Editor, Faction Relationship Map. Quests are edited as `QuestAsset`s; dialogue and faction editors are planned
- `SkillManager`: its storage helpers are `protected virtual` (they were private stubs, so learning a skill always failed); a game supplies storage by overriding them
- **Fix: `DeltaSerializer` rebuilt wrong states.** Proven before: a state that grew lost its new bytes, one that shrank kept stale ones, a delta built on a state the receiver never got (a lost packet) was applied silently, and a broken packet threw `EndOfStreamException`. Now a delta carries the new length and the length and checksum of the state it was built on: the receiver refuses a delta for a state it does not have (`InvalidOperationException`; the sender calls `ClearState` and sends a full state) and a broken packet (`InvalidDataException`), keeping its state. Changes are sent as byte runs, cheaper than the old 5 bytes per changed byte. The wire format changed (`DeltaSerializerTests`)
- **Fix: designer assets in `Tools`.** The loot table editor showed wrong drop rates when a table had an entry without an item (it counted weight the game never rolls: 37.5% shown for 75%). An empty prerequisite slot locked a quest forever; a quest asset made in code failed to convert (`NullReferenceException`). Checking a quest database with long branching chains froze the editor (17 s for 20 chapters; now each quest is walked once). Loot checks report entries whose max level is below their min level (they never drop). Consumable items get their effect from the asset (`ItemAsset.effectId`, `effectMagnitude`; the old placeholder stays the default) (`ToolsAssetTests`)
- **Fix:** the debug tools in `RPGFramework.Tools` (event logger, console, debugger, profiler, health monitor) read keys through the legacy input manager only and threw every frame in a game that uses only the Input System; they now read either, like `DiagnosticsOverlay`
- **Stats recalculate 18 times faster and allocate nothing.** `StatContainer` kept LINQ queries, sorting and boxing in every recalculation: a thousand characters with six modifiers each took 7.3 ms a frame and made garbage every time. Modifiers are now kept in priority order as they are added and summed in one pass without conversions that box: 0.4 ms a frame, no garbage (`StatContainerPerformanceTests`, with the benchmark numbers in the test output). Same results: an override still wins by priority, additives then multipliers in priority order
- **Fix:** a whole-number stat pushed past its type's limit (`int.MaxValue` plus a bonus) threw `OverflowException`; it now stops at the limit.
- **Saves outlive the build that made them.** Each save section carries its participant's version (`ISaveParticipant.Version`, `SaveParticipant<T>.Version` / `Upgrade`): older sections are upgraded by the participant, saves from before section versions load as version 1, and a save from a newer build is refused before anything changes (`SaveGameState` format 2). `SaveGameCoordinator.LastUpgradedSections`
- **A save is never lost to a bad load.** `SaveSystem` keeps the previous save beside the latest (`<slot>.previous.sav`, only when it was intact) and loads it when the latest fails its checksum or cannot be read (`LoadResult.FromPrevious`, `ISaveSystem.LoadPrevious<T>`); the coordinator falls back the same way when the latest is intact but its sections cannot be used. `SaveSystem.SetAside` moves an unreadable save out of the slot. `ActionRpgSaves`: unreadable saves are kept aside and the game starts fresh, a newer build's save is not saved over (`CanSave`, `Notice`), and the game log tells the player
- **Fix: the JSON save serializer** (`JsonSaveSerializer`, also inside `BinarySaveSerializer`) is rewritten as a real parser. Proven broken before: text ending in a quote or a backslash came back wrong or swallowed the next field; a literal `\n` became a line break; a dictionary key with `:` made the save unloadable; `DateTime`, `Guid` or a cycle overflowed the stack while saving; truncated text loaded silently. Now: full escaping, enums by name, `DateTime`/`DateTimeOffset`/`TimeSpan`/`Guid`/`decimal`/nullable/all integer types, sets, get-only collections, a depth limit with a clear error, strict text and tolerant shape (unknown members skipped, missing keep defaults). Older saves still load (enums as `{"value__":n}`, number keys without quotes)
