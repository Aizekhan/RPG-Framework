# Reference Game: Goblin Valley

A small game built only on framework assemblies. It shows how a game is composed and proves, in automated tests,
that the framework modules work together.

## Composition

`GoblinValleyComposition.Configure` adds the modules to `GameHost`. The scene host and the tests share it:

| Module | Gives the game |
|---|---|
| `FrameworkCoreModule` (added by `GameHost`) | event bus, entities, systems, timers, world |
| `CombatModule` | `ILifeStateManager` (deaths/resurrections on the bus), `IDamageCalculator` |
| `ProgressionModule` | `IProgressionTracker`, `IStatGrowthFormula`; level-ups publish `StatIncreasedEvent` |
| `QuestsModule` | `IQuestRegistry`, `IQuestManager` |
| `ItemsModule`, `LootModule` | item registry, loot tables and generator |
| `CombatQuestsModule` | kills advance Kill objectives |
| `GoblinValleyModule` | the game's content and rules (`GoblinValleyGame`) |

## Rules are bus subscriptions

| Event | Rule |
|---|---|
| `DeathEvent` (goblin) | kill XP and a loot roll for the killer; the goblin is despawned |
| `ObjectiveProgressedEvent` (completed) | the quest is turned in |
| `QuestCompletedEvent` | XP and item rewards |
| `StatIncreasedEvent` | the new stat value is applied to the hero's `StatContainer` |
| `LevelUpEvent` | the hero is healed |
| `ItemAddedEvent<IItem>` | the HUD log |

## Game rules and the scene are separate

```
Scripts/Core   ReferenceGame.Core (noEngineReferences): GoblinValleyGame, GoblinWaveSystem, content, events
Scripts/View   ReferenceGame: prefabs bound to entities, input, HUD
```

`Tests/ReferenceGameArchitectureTests` runs the framework's game architecture rules (GA01–GA10) on this game.

The rules announce combatants entering and leaving the valley (`CombatantSpawnedEvent`, `CombatantDespawnedEvent`).
`GoblinValleyPresenter` answers by spawning the prefab registered for the combatant's kind (`player`, `goblin`)
through the framework `PrefabSpawner` (goblins are pooled). It links the view to the entity in the framework
`EntityViewRegistry` and binds the `CombatantView` components on it:

| Component | Does |
|---|---|
| `HeroController` | moves the hero (Input System) and calls `GoblinValleyGame.Attack` on the nearest goblin in reach |
| `GoblinBrain` | chases the hero, keeps apart from other goblins, strikes on a cooldown |
| `HealthBarView` | health bar facing the camera, hit flash |
| `StrikeAnimator` | lunge of the model when striking |

Views never change game state themselves; they call the game API, and the rules decide.

## Tune it in the inspector

| Asset / object | What to tune |
|---|---|
| `Config/GoblinValleyConfig` | waves (delays, sizes), loot seed, spawn radius, which prefab catalog |
| `Config/GoblinValleyPrefabs` | prefab per kind, pooling |
| `Prefabs/Hero`, `Prefabs/Goblin` | models, speeds, attack range and cooldown, health bar |
| `GoblinValleyHost` (scene) | config, camera |

The prefabs, materials and scene layout are placeholders generated by **RPG Framework → Reference Game → Rebuild
Goblin Valley** (`Editor/GoblinValleyBuilder`). Rebuilding replaces the two prefabs; the config, catalog and materials
are only created when missing. To use real art, edit the prefabs or point the catalog at your own prefabs, and stop
rebuilding.

## Play

Open `Scenes/GoblinValley.unity` and press Play. Waves of goblins come at the hero, one bigger than the last.

- **Move**: WASD, arrows or the left stick
- **Attack**: Space, left mouse button or the gamepad south button
- **Respawn**: R or Start

## Tests

`Tests/GoblinValleyTests` boots the game through `GameHost` and checks:

- every module is registered;
- clearing the valley runs the whole chain: death → quest → turn-in → XP → level-up → stat growth, plus loot into the backpack;
- the world ticks without errors;
- a failing event handler is logged and the game keeps running;
- a missing module fails the start loudly;
- shutdown is clean.

`GoblinValleyWaveTests` checks the waves (delay, growth, pause while the hero is dead) and the spawn and despawn
announcements. `GoblinValleySceneTests` checks that the scene has its host, wired to a config with both prefabs and a
camera. `PlayTests/GoblinValleyPlayTests` (PlayMode) plays the scene: the hero and a wave appear, goblins chase, the
hero's strike reaches the rules and slain goblins leave the scene.
